# دليل المستخدم — نظام إدارة الشؤون القانونية

## 1. مساحة العمل والبطاقات

مساحة العمل **نظام إدارة الشؤون القانونية** (المسار: `/app/legal-management`) تحتوي على:

- **بطاقات مؤشرات (Number Cards)**: القضايا المفتوحة، العقود النشطة، الشكاوى المفتوحة،
  قرارات قيد الانتظار، الجلسات القادمة، طلبات الرأي المفتوحة، اللجان النشطة.
- **مخططات (Charts)**: القضايا حسب الحالة، العقود حسب الحالة، الشكاوى حسب الحالة،
  الشكاوى حسب جهة الاختصاص، المصروفات حسب النوع.
- **بطاقات روابط (Card Break)** على نمط وحدة الموارد البشرية:

| البطاقة | المحتوى |
|---|---|
| القضايا والجلسات | قضية قانونية، جلسة قانونية، مستشار قانوني |
| العقود والالتزامات | عقد قانوني، التزام تعاقدي |
| الآراء القانونية | طلب رأي قانوني، رأي قانوني |
| شكاوى الموظفين | شكوى موظف، سجل إجراءات الشكوى |
| لجان شكاوى الموظفين | لجنة شكاوى الموظفين، اجتماع لجنة شكاوى الموظفين |
| المراسلات والمستندات | مراسلة قانونية، سجل المستندات القانونية |
| المصروفات والقرارات | مصروف قانوني، قرار قانوني |
| الإعدادات | إعدادات الشؤون القانونية |
| التقارير | خمسة تقارير تشغيلية (انظر §6) |

## 2. القضايا والجلسات

1. إنشاء **قضية قانونية** (مسودة) مع العنوان والنوع وتاريخ التسجيل.
2. التحرك عبر الـ Workflow: `تسجيل القضية ← بدء المراجعة ← تكليف القضية ← بدء التنفيذ
   ← جدولة الجلسة / طلب المستندات ← انتظار الحكم ← إصدار الحكم ← استئناف / تسوية ← إغلاق ← أرشفة`.
3. إضافة **جلسة قانونية** مرتبطة بالقضية: يتم تحديث `next_hearing_date` في القضية تلقائيًا،
   وتُنشأ الجلسات فقط بتاريخ مستقبلي.
4. لا يمكن حذف قضية غير مسودة أو أرشفتها إلا من **مدير النظام القانوني**.

## 3. العقود والالتزامات

- المسار: `مسودة ← قيد المراجعة القانونية ← إعادة للتعديل / بانتظار الاعتماد ← بانتظار
  التوقيع ← نشط ← قارب على الانتهاء / منتهٍ / مجدد ← مؤرشف`.
- **الطرف المرتبط** مطلوب قبل إحالة العقد للمراجعة، مع اسم الطرف.
- **تفعيل العقد** يتطلب تاريخي البداية والنهاية، والنسخة الموقعة وتاريخ التوقيع
  (إعداد `contract_activation_requires_signature`)، وسجل تواريخ الاعتمادات يُبنى تلقائيًا.
- **التزام تعاقدي** مرتبط بالعقد له تاريخ استحقاق وتكرار (شهري/ربع/نصف سنوي/سنوي).

## 4. طلبات الرأي والقرارات

- طالب الرأي: `مسودة ← مقدمة ← قيد المراجعة ← بانتظار التوضيح ← مسودة رأي ← قيد المراجعة
  القانونية ← بانتظار الاعتماد ← معتمدة / مرفوضة ← مغلقة`.
- الطلب الذي أُرسل لا يعدّله الطالب إلا في حالة المسودة، والمخالفات مرفوضة.
- **قرار قانوني** يُنشأ كسجل مستقل، ويُمنع تعديله بعد الاعتماد، و**فصل المُعِدّ عن المعتمد**
  مطبَّق: من أعدّ التوصية لا يستطيع اعتماد القرار بنفسه.

## 5. شكاوى الموظفين (المساران)

### آلة الحالات

```
مسودة → مقدمة
├─ مسار الشؤون القانونية: قيد المراجعة القانونية ⇄ بانتظار المعلومات → توصية قانونية → بانتظار القرار
└─ مسار لجنة شكاوى الموظفين: قيد مراجعة اللجنة ⇄ بانتظار المعلومات → توصية اللجنة → بانتظار القرار
بانتظار القرار → صدر القرار → مغلقة (أو مرفوضة)
```

### الإجراءات المتاحة (تُطبَّق من زر الإجراء في نموذج الشكوى)

| الإجراء | صلاحيته | الأثر |
|---|---|---|
| قبول الشكوى وبدء المراجعة | مسؤول الشكاوى / اللجنة | ينقل الشكوى لمسار المراجعة ويحدد المسؤول |
| طلب معلومات من الموظف | مسؤول الشكاوى / اللجنة | حالة «بانتظار المعلومات» + توضيح مطلوب |
| استئناف المراجعة | مسؤول الشكاوى / اللجنة | العودة لحالة المراجعة |
| إعداد التوصية القانونية | مسؤول الشكاوى القانونية | ت��صية موثقة + اسم معدّها |
| إعداد توصية اللجنة | رئيس/أمين اللجنة | توصية موثقة |
| جدولة اجتماع اللجنة | رئيس/أمين اللجنة | ربط اللجنة وتحديث آخر اجتماع |
| بدء مداولات اللجنة | رئيس/أمين اللجنة | حالة «تحت مداولة اللجنة» |
| إحالة الشكوى للقرار | مسؤول المراجعة | لا تُقبل قبل توثيق التوصية |
| إصدار القرار | المعتمد المخوّل | إنشاء **قرار قانوني** وربطه بالشكوى |
| إغلاق الشكوى | مسؤول المراجعة | يتطلب قرارًا مسجلًا وسببًا للإغلاق |

### قواعد صارمة

- جهة الاختصاص لا تُترك فارغة: يجب اختيار **إدارة الشؤون القانونية** أو **لجنة شكاوى
  الموظفين** قبل التقديم.
- **الموظف لا يقدّم شكوى نيابة عن موظف آخر** إلا إذا فُعّل الإعداد
  `allow_grievance_on_behalf` وكان للمستخدم دور معتمد.
- بعد التقديم لا تُعدَّل الحقول المحكومة (الحالة، جهة الاختصاص، التوصية، القرار…)
  إلا عبر الإجراءات الموثقة أعلاه.
- كل إجراء يُنشئ صفًا في **سجل إجراءات الشكوى** (غير قابل للتعديل أو الحذف).
- تحويل الاختصاص بين المسارين يتطلب سببًا، ويمسح التوصية السابقة ويُعيد الحالة إلى «مقدمة».

## 6. اللجان والاجتماعات

- **لجنة شكاوى الموظفين** تتطلب رئيسًا وأمينًا وأعضاءً لتفعيلها، وتحدد نسبة النصاب.
- **اجتماع اللجنة** يحسب النصاب تلقائيًا من الأعضاء الحاضرين، ولا يكتمل بدون محضر ونصاب.
- **اعتماد المحضر** يتطلب دور **رئيس اللجنة** (أو مدير النظام القانوني) ولا يجوز لمعدّ
  المحضر اعتماده بنفسه.
- لا يمكن تكرار الشكوى نفسها في جدول الأعمال.

## 7. المصروفات والمراسلات والمستندات

- **مصروف قانوني**: `مسودة ← بانتظار المراجعة ← معتمد / مرفوض ← مدفوع`، والاعتماد يتطلب
  مدير الشؤون القانونية، والرفض يتطلب سببًا.
- **مراسلة قانونية** و**سجل مستندات قانوني** يمكن ربطهما بشكوى (`related_grievance`)،
  وعندها تتبعان نطاق صلاحية الشكوى الأم (لا يراها إلا من يحق له رؤية الشكوى).
- **المرفقات**: كل مرفق على سجل قانوني يُجبَر على `is_private = 1`، ولا يمكن نقله من
  سجل إلى آخر.

## 8. الإعدادات (`Legal Settings`)

| الإعداد | الأثر |
|---|---|
| `default_company` / `default_currency` | الشركة والعملة الافتراضية للسجلات |
| `enable_email_notifications` | إرسال بريد إلكتروني مع الإشعارات داخل النظام |
| `enable_scheduler_alerts` | تفعيل مهمة التنبيهات اليومية |
| `allow_grievance_on_behalf` | السماح بإنشاء شكوى نيابة عن موظف آخر |
| `allow_opinion_on_behalf` | السماح بإنشاء طلب رأي باسم مستخدم آخر |
| `hearing_alert_days` | نافذة التنبيه قبل الجلسة (افتراضي 3) |
| `contract_expiry_alert_days` | نافذة تنبيه انتهاء العقد (افتراضي 30) |
| `obligation_due_alert_days` | نافذة تنبيه استحقاق الالتزام (افتراضي 7) |
| `opinion_due_alert_days` | نافذة تنبيه استحقاق الرأي (افتراضي 3) |
| `meeting_alert_days` | نافذة تنبيه اجتماع اللجنة (افتراضي 2) |
| `grievance_stale_days` | الحدّ الذي تُعتبر بعده الشكوى «متأخرة» (افتراضي 14) |
| `contract_activation_requires_signature` | اشتراط النسخة الموقعة للتفعيل |
| `grievance_close_requires_decision` | اشتراط قرار مسجل قبل الإغلاق |
| `grievance_decision_separation_required` | منع معدّ التوصية من اعتماد القرار |
| `committee_quorum_percent` | نسبة النصاب الافتراضية (1–100) |
| `alert_recipients` | مستلمو التنبيهات حسب النطاق (All/Cases/Contracts/Opinions/Committee) |

## 9. التنبيهات المجدولة

مهمة `bank_legal_management.tasks.process_legal_deadlines` تعمل يوميًا وتُنشئ سجلات في
**سجل التنبيهات القانونية** (بدون تكرار) لِ:

- الجلسات القادمة، انتهاء/قرب انتهاء العقود، الالتزامات المستحقة، طلبات الرأي المستحقة،
  اجتماعات اللجنة، الشكاوى المتأخرة عن مدة المعالجة.

## 10. التقارير

| التقرير | المحتوى |
|---|---|
| سجل القضايا | كل القضايا مع النوع والحالة والمسؤول |
| سجل العقود | العقود مع الحالة والقيمة والفترة |
| سجل شكاوى الموظفين | الشكاوى مع الموظف وجهة الاختصاص والحالة |
| الاستحقاقات القانونية | الجلسات/العقود/الالتزامات/الآراء المستحقة |
| ملخص المصروفات القانونية | المصروفات حسب النوع والحالة |

## 11. واجهات API (Whitelisted)

| الدالة | الأثر |
|---|---|
| `get_available_grievance_actions(name)` | الإجراءات المسموحة للمستخدم الحالي |
| `apply_grievance_action(name, action, notes, recommendation, committee)` | تنفيذ إجراء موثق |
| `provide_grievance_information(name, response_text)` | رد الموظف على طلب المعلومات |
| `transfer_grievance_jurisdiction(name, new_jurisdiction, reason)` | تحويل الاختصاص |
| `issue_grievance_decision(name, decision_text)` | إصدار القرار (للمعتمد المخوّل) |
| `get_grievance_timeline(name)` | سجل الإجراءات والتوضيحات |
| `approve_committee_minutes(name)` | اعتماد محضر الاجتماع |
| `submit_expense_for_review` / `approve_legal_expense` / `reject_legal_expense` / `mark_legal_expense_paid` | دورة المصروف |
| `request_opinion_clarification` / `provide_opinion_clarification` | دورة التوضيح |
| `approve_legal_opinion(name)` | اعتماد نسخة الرأي |

جميع الدوال تتحقق من صلاحية المستخدم على السجل قبل التنفيذ (لا تُنفَّذ أي عملية بصلاحيات
مرفوعة).
